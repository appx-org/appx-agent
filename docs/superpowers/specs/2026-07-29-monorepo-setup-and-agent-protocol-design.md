# appx-agent monorepo setup + agent-protocol carve-out — design

**Date:** 2026-07-29
**Status:** approved

## Context

`appx-agent` was assembled from the `agent-server` and `agent-client` repos via
`git filter-repo` (full history preserved; the two package directories currently
sit at the repo root with no shared tooling). Three artifacts will ship from
this repo:

- **`@appx-org/agent-server`** — private package, published as a **docker image**.
- **`@appx-org/agent-client`** — React UI package, published as **npm package**
  to GitHub Packages.
- **`@appx-org/agent-protocol`** (new) — the shared API contract (REST + SSE)
  as types and JSON artifacts, published as **npm package** to GitHub Packages.

Motivating consumer for `agent-protocol`: a planned appx-like TypeScript control
plane that deploys agent-server containers, creates projects, and assigns ports.
It needs typed access to the contract without pulling in a React UI package.
`appx` (Go) stays in its own repo and consumes the published `openapi.json`.

## Problem being solved

Today the contract crosses the package boundary as a **vendored snapshot**:
agent-server generates `openapi.json`, agent-client keeps a hand-copied
`openapi/agent-server.json` and runs `openapi-typescript` over it. Nothing
forces the copy to stay fresh. The monorepo + protocol package replaces the
snapshot with a real dependency edge, guarded by the existing
regenerate-and-diff freshness gate.

## Decisions (settled with user)

| Topic | Decision |
| --- | --- |
| Protocol scope | Generated artifacts **plus** friendly type aliases (`AgentProject`, `WireEvent`, …) moved out of agent-client |
| Versioning | Changesets, independent versions per package |
| Builds | All published packages build real `dist/` (tsc, declarations); client keeps `src/` in tarball |
| Layout | `packages/*`; tooling (biome, husky, CI, tsconfig base) hoisted to root |
| Lint/format | Biome repo-wide (pi conventions: tabs, indent width 3, lineWidth 120); one-time reformat of agent-client |
| Naming | Everything under `@appx-org/*`; agent-server renamed from `@appx/agent-server`, stays `private: true` |
| Contract flow | **Option A** — protocol package is the artifact home; generation runs in agent-server and writes there (see below) |

## Architecture

### Layout

```
appx-agent/
├── package.json               # private root: npm workspaces, shared scripts
├── package-lock.json          # single root lockfile (workspaces)
├── biome.json                 # repo-wide formatter/linter config
├── tsconfig.base.json         # shared strict compiler options
├── .husky/pre-commit          # hoisted hook: biome + typecheck + contract regen
├── .github/workflows/
│   ├── ci.yml                 # check, typecheck, test, contract freshness
│   ├── container-smoke.yml    # existing nightly, paths updated
│   └── release.yml            # changesets → npm publish + docker build
├── .changeset/config.json
├── docs/                      # repo-level docs (incl. this spec)
└── packages/
    ├── agent-protocol/
    │   ├── package.json               # @appx-org/agent-protocol
    │   ├── openapi.json               # GENERATED by agent-server's gen scripts
    │   ├── eventSchema.generated.json # GENERATED (typia over WireEvent)
    │   └── src/
    │       ├── generated.ts           # GENERATED openapi-typescript output (paths, components)
    │       ├── types.ts               # friendly aliases, moved from agent-client
    │       └── index.ts               # re-exports; also exports the JSON artifacts' paths
    ├── agent-server/                  # moved from /agent-server (git mv)
    └── agent-client/                  # moved from /agent-client (git mv)
```

### Dependency edges (all one direction)

```
agent-server ──▶ agent-protocol ◀── agent-client
```

- **agent-server → protocol (runtime):** `eventValidation.ts` loads the event
  schema JSON from the protocol package instead of a local copy; the copied
  `dist/contract/eventSchema.generated.json` build step goes away. Server code
  keeps using pi's TypeScript types internally (it is the *producer*; the
  generated consumer types would be circular).
- **agent-client → protocol (types):** `agent-server.generated.ts`,
  `openapi/agent-server.json`, and the `gen:api` script are **deleted** from
  agent-client. `src/core/types.ts` shrinks to the UI-derived types
  (`UiMessage`, `SessionState`, `initialSessionState`) and re-exports the
  contract types from protocol, so agent-client's **public API is unchanged**.
  `client.ts` imports `paths` from `@appx-org/agent-protocol`.

### Contract pipeline (single direction, one copy of each artifact)

```
zod REST schemas + pi WireEvent types        (source of truth, in agent-server)
        │  npm run gen:event-schema && npm run openapi   (run in agent-server;
        ▼                                                 typia needs ts-patch)
packages/agent-protocol/{openapi.json, eventSchema.generated.json}
        │  npm run gen:types                 (run in agent-protocol;
        ▼                                     openapi-typescript)
packages/agent-protocol/src/generated.ts     (committed)
```

Generation must run *in* agent-server because `openapi.ts` imports live route
code and typia requires the server's ts-patch toolchain. Only the **outputs**
move to protocol. A root script `npm run gen` chains both halves.

`OPENAPI_INFO.version` (currently hand-maintained in
`openapiEventSchema.ts`) is replaced by reading agent-protocol's
`package.json` version — the protocol package version **is** the contract
version.

### Freshness guarantees (same mechanism as today, wider coverage)

- **Pre-commit (root husky):** biome check + typecheck always; when staged
  files touch `packages/agent-server/src/**`, `packages/agent-protocol/src/**`
  (non-generated), or dependency manifests, regenerate the full chain and
  re-stage the artifacts.
- **CI freshness gate:** regenerate everything, `git diff --exit-code`. Catches
  anything the hook misses.

## Package details

### agent-protocol (`@appx-org/agent-protocol`)

- `exports`: `.` → dist (types + JS for the aliases and generated types);
  `./openapi.json` and `./event-schema.json` → the raw JSON artifacts (for
  non-TS consumers and the server's runtime validation).
- No runtime dependencies. `openapi-typescript` as devDependency.
- Contents of `types.ts`: the contract-derived aliases currently in
  agent-client's `types.ts` (`ThinkingLevel`, `AgentProject`,
  `AgentSessionInfo`, `AgentModel`, `AgentSessionModelSettings`,
  `ExtensionUiResponse`, auth/provider DTOs, `WireEvent`, `AgentEvent`,
  `ExtensionUiRequest`, message/content-block types, …). UI-derived types stay
  in agent-client.
- Smoke test: generated types compile; both JSON artifacts parse and are
  non-empty.

### agent-server (`@appx-org/agent-server`, private)

- `git mv agent-server packages/agent-server`; package renamed.
- Loses: local `openapi.json`, `src/contract/eventSchema.generated.json`
  (now in protocol), the dist-copy build step, husky + biome + `prepare`
  script (hoisted), its `.github/` (hoisted, paths updated).
- Keeps: all source, `gen:event-schema` + `openapi` scripts (now writing into
  `../agent-protocol/`), tests, container/ and builder-agent/ assets.
- `GET /openapi.json` and `/docs` keep working — the live document is built by
  `buildOpenApiDocument()` as today; only the static dump location changed.
- **Dockerfile:** already builds from repo root; updated for workspaces — copy
  root manifest + lockfile + the two workspace manifests (server + protocol),
  `npm ci`, build protocol then server, prune to production. agent-client is
  never copied in. `.dockerignore` updated accordingly.

### agent-client (`@appx-org/agent-client`)

- `git mv agent-client packages/agent-client`.
- Gains dependency on `@appx-org/agent-protocol` (workspace-resolved locally,
  semver range when published).
- Gets a real `dist/` build: `exports` point at `dist/*.js` + `dist/*.d.ts`
  (with declarationMap + sourceMap); `src/` remains in `files` so IDEs and
  source-following bundlers still work. `./styles.css` export unchanged.
- vitest setup unchanged; tests move with the package.
- One-time biome reformat (separate commit, so blame damage is contained).

## Root tooling

- **Root `package.json`:** `private: true`, `workspaces: ["packages/*"]`,
  scripts: `check`, `typecheck`, `test`, `build`, `gen` (fan out via
  `npm run <s> --workspaces --if-present` or explicit `-w` chains where order
  matters: protocol builds before server/client).
- **`tsconfig.base.json`:** merge of the two existing configs, taking the
  stricter union (agent-client's base already has `noUncheckedIndexedAccess`,
  `verbatimModuleSyntax`, etc.). Per-package tsconfigs extend it. Workspace
  cross-package resolution via published `exports` (dist), not path mapping —
  packages must build in dependency order, which the root `build` script
  encodes.
- **biome.json:** agent-server's config moved to root, scope widened; ignores
  `**/dist`, `**/*.generated.*`, `packages/agent-protocol/src/generated.ts`.
- **husky:** hoisted to root (`prepare` script at root). Pre-commit logic as
  today, paths adjusted, plus the openapi-typescript step.
- **CI (`ci.yml`):** node 22, `npm ci`, root `check` + `typecheck` + `build` +
  `test`, then the freshness gate. `container-smoke.yml` keeps its
  nightly/dispatch triggers with updated paths.
- **`release.yml`:** changesets action on main — opens/updates a "Version
  Packages" PR; on merge, publishes changed npm packages to GitHub Packages
  and builds/pushes the agent-server docker image tagged with the server
  package version.

## Versioning & compatibility

- Changesets, **independent versions**. agent-protocol's version is the
  contract version; server and client depend on it via caret ranges, which
  documents which contract each published version speaks.
- agent-client public API is a superset of today's (same exports, now partly
  re-exported from protocol) — no breaking change for lanquest/quest;
  consumers may keep importing everything from `@appx-org/agent-client`.

## Error handling / failure modes

- **Stale artifacts:** pre-commit regen + CI diff gate (two nets, as today).
- **Build-order mistakes:** root `build` script encodes protocol-first order;
  CI runs it, so a wrong local build can't land green.
- **Docker image accidentally including agent-client:** the Dockerfile copies
  only the server + protocol workspace manifests before `npm ci`, so the
  client workspace never enters the image; smoke workflow still boots the
  image as a regression net.
- **Old repos:** remain live as archives; the `file:` consumers (lanquest)
  keep working against old checkouts until repointed at
  `appx-agent/packages/agent-client`. Out of scope here, but noted.

## Migration plan (commit-per-step, git mv throughout)

1. `git mv agent-server packages/agent-server`, `git mv agent-client
   packages/agent-client`; root `package.json` + lockfile bootstrap.
2. Hoist tooling: biome, husky, tsconfig.base, `.github` (path updates).
   One-time biome reformat of agent-client as its own commit.
3. Create `packages/agent-protocol`; move generation outputs + friendly
   aliases; rewire server gen scripts and `eventValidation.ts`.
4. Rewire agent-client onto protocol; delete vendored spec + `gen:api`;
   add dist build.
5. Update Dockerfile + `.dockerignore` for workspaces.
6. Changesets init + `release.yml`.
7. Full verification: root `check`/`typecheck`/`build`/`test`, freshness gate
   clean, docker build succeeds, client tarball (`npm pack`) contents sane.

## Out of scope

- Repointing lanquest/quest/appx at the new packages or registry.
- Publishing the first release (user will trigger when ready).
- Transplanting feature branches from the old repos.
- Turbo/nx build caching — npm workspaces scripts are sufficient at 3 packages.
